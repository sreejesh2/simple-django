Today everyone uses this laptop over the Wi-Fi. Render gives the same site a public link that works from anywhere. This is a class demo, not a production setup.

  • You need: GitHub and a free Render account
  • Time: about 15 minutes
  • Result: a link like your-app.onrender.com

  1. Know who does what

    • Render runs the Django website
    • Supabase stores the rows (title, image path)
    • Cloudinary stores the image files

    Render only replaces your laptop. Supabase and Cloudinary stay exactly the same.

  2. Get the project ready

    Your laptop uses runserver. Render needs two more packages:

    • Gunicorn runs Django on the server
    • WhiteNoise serves your CSS and JS (Gunicorn does not do that by itself)
    requirements.txt 
    Django==5.1.4
cloudinary
django-cloudinary-storage
Pillow
python-dotenv
psycopg[binary]
gunicorn
whitenoise

    Add WhiteNoise right after the security middleware, and tell Django where to collect static files:

    config/settings.py 
    MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',
    'whitenoise.middleware.WhiteNoiseMiddleware',
    # ... the rest stay the same ...
]

STATIC_ROOT = BASE_DIR / 'staticfiles'

    ALLOWED_HOSTS: this demo uses ALLOWED_HOSTS = ['*'], so the Render address works without extra setup.

  3. Push the code to GitHub

    Terminal 
    git add .
git commit -m "ready for render"
git push origin main

    Check first: .env must be in .gitignore. Your keys go into Render in step 6, not into GitHub.

  4. Start a new Web Service

    1. Sign in at render.com with your GitHub account
    2. Click + New → Web Service
    3. Choose Git Provider and pick your repository

    Render now shows a form. Step 5 explains every field.

  5. Fill in the form, field by field

    Name
    mams-django-workshop
    Becomes your link: mams-django-workshop.onrender.com. Lowercase letters and dashes only.
    Project optional
    Leave as it is
    Only groups services in the dashboard. Not needed for one app.
    Language
    Python 3
    Django is a Python framework.
    Branch
    main
    Render deploys this branch, and redeploys every time you push to it.
    Region
    Singapore (Southeast Asia)
    Closest to India and to the Supabase database, so pages load faster. Oregon works too, just slower.
    Root Directory optional
    Leave empty
    manage.py is already at the top of the repo. Only fill this if your project is inside a subfolder.
    Build Command
    Copy the block below
    Runs once per deploy: installs packages, gathers CSS, creates tables.
    Build Command 
    pip install -r requirements.txt && python manage.py collectstatic --noinput && python manage.py migrate
    Start Command
    Copy the block below
    Starts the site. config is the folder that holds settings.py and wsgi.py.
    Start Command 
    gunicorn config.wsgi:application
    Instance Type
    Free
    Enough for a class demo. It sleeps after about 15 minutes with no visitors.

  6. Add environment variables

    Scroll to Environment Variables on the same form. Click Add from .env and paste these lines with your own values:

    Environment Variables 
    PYTHON_VERSION=3.12.0
CLOUDINARY_CLOUD_NAME=your_cloud_name
CLOUDINARY_API_KEY=your_api_key
CLOUDINARY_API_SECRET=your_api_secret
SUPABASE_DB_NAME=postgres
SUPABASE_DB_USER=postgres.your_project_ref
SUPABASE_DB_PASSWORD=your_password
SUPABASE_DB_HOST=aws-0-ap-northeast-2.pooler.supabase.com
SUPABASE_DB_PORT=5432

    Same as .env: Render cannot see your laptop's .env, so it needs its own copy. PYTHON_VERSION makes Render use the same Python as your laptop.

    Use the Session pooler: keep the pooler.supabase.com host and the postgres.xxxx user. The direct db.xxxx.supabase.co host will not connect.

  7. Deploy and watch the logs

    1. Click Deploy Web Service at the bottom
    2. Watch the log. The first build takes 2 to 5 minutes
    3. Wait for Your service is live 🎉
    4. Click the link at the top of the page

    Good signs in the log: static files copied, then Applying ... OK or No migrations to apply, then Booting worker.

  8. Create an admin login

    The free plan has no Render Shell. You don't need it: your laptop and Render use the same Supabase database, so run this on your laptop:

    Terminal (your laptop) 
    python manage.py createsuperuser

    Then open https://your-app.onrender.com/admin/, log in, and upload a photo. It appears on the home page, from Cloudinary.

  9. If something goes wrong

    Build failed
    A package is missing from requirements.txt. Add it, push again, and Render redeploys.
    Page has no styling
    WhiteNoise is missing from MIDDLEWARE, or collectstatic is missing from the build command.
    Database connection error
    Check the SUPABASE_DB_* values. Use the Session pooler host and the postgres.xxxx user.
    Images don't upload
    Check the three CLOUDINARY_* values in Environment.
    First visit is very slow
    Normal on the free plan. The app was asleep and takes about a minute to wake.
